math_utils.h:
The header file contains the signature of the square functions, giving the information that it accepts an integer parameter, and returns an integer. It allows the main.c to know that the function exists.


math_utils.c:
Contains the actual implementation of square() function.


main.c:
Initializes n to 4, and calls square(n). Prints both results in the standard output.


First, the program was compiled into obj files without linking:
gcc -c main.c 
gcc -c math_utils.c


-c flag stops the compilation and produces -o obj file instead of an executable file
So, in result, we got two object files: main.o math_utils.o


Then I linked the two obj files together getting a final executable.
gcc main.o math_utils.o -o square_prog

The role of the linker:
The linker is responsible for combining separately compiled object files into a single executable.
main.o contains a reference to square(), but does not contain its implementation. math_utils.o contains the implementation and the linker resolves this relationship and places both pieces of code into the final executable. It also performs relocation, meaning it updates references in the machine code so that calls and addresses point to the correct locations.
